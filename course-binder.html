目标：6 周内从「知道 binder 设计」到「独立完成一个 mini-protein binder 设计项目」，产出可送实验验证的候选序列。

第 1 周：建立全流程心智 + 选定靶点

预计 3–4 小时 · 产出：一份「靶点分析报告」

1.1 先建立整体心智地图

现代 binder 设计是一条标准流水线，先把五个环节刻进脑子里，之后每周只是把某一环做深：

  1. 选靶点 + 定义界面：决定要结合目标蛋白的哪个表面、哪个「热区」；
  2. 生成骨架：RFdiffusion 对着靶点生长一条全新 mini-protein（binder）骨架；
  3. 设计序列：ProteinMPNN 把骨架「翻译」成氨基酸序列；
  4. 回测验证：AlphaFold/ColabFold 预测「设计序列会折叠成什么样」，和设计骨架对比；
  5. 实验验证：表达、纯化、结合实验（酵母展示/BLI/SPR/cryo-EM）。

你现在要理解的核心论文与工具对应关系：热区/界面 → Cao 2022；骨架生成 → RFdiffusion 2023；序列设计 → ProteinMPNN 2022；回测闭环 → AlphaFold/ColabFold。

1.2 选定你的靶点（本周最重要的决定）

课程成功的一半取决于靶点选得好不好。选靶点四条原则：

  • 有高质量结构：PDB 里有分辨率较好的单体结构（≤3 Å，覆盖你要结合的界面）；
  • 有明确生物学动机：阻断某个相互作用、靶向某个疾病相关蛋白——动机清楚，故事才成立；
  • 结构域不要太大太柔性：优先选 100–400 aa 的球状结构域作为结合面，避免大片无序区；
  • 你自己能验证：你有表达/结合实验条件（或能合作）——没有验证闭环，设计只是 PPT。

示例（可当练习靶点）：SARS-CoV-2 RBD（PDB 6M0J）、流感 HA、你实验室关心的 RNR 亚基界面——拿熟蛋白练手最省心。

1.3 实操：把靶点结构拉到本地并「看一眼」

  1. 去 RCSB 搜你的蛋白，下载 PDB 文件（优先下载 biological assembly 或你关心的单链）；
  2. 用 ChimeraX 打开：open 6m0j.pdb；
  3. 确认你想要的结合表面 没有 被糖基化/无序区/其他链遮挡；
  4. 把「想阻断的天然相互作用伙伴」结构也打开（如果有），看它到底结合在哪个表面——你的 binder 要抢占的正是这块。

1.4 环境自检（一次配好，六周复用）

  • Google 账号（用 Colab）；
  • ChimeraX（本地可视化，本周已用）；
  • 能打开并运行 RFdiffusion Colab（本周只需跑到安装完成即可，不用出结果）；
  • 会读 pLDDT/pTM（复习 术语表 与免费实操任务「ColabFold 第一次预测」）。

1.5 本周作业（产出模板）

写一份 1 页靶点分析报告，包含：①靶点名称与 PDB ID；②想阻断的相互作用/生物学动机（2–3 句）；③拟结合表面截图 + 一句话说明为什么选这块；④你判断的难点（柔性/糖基化/无已知相互作用伙伴）；⑤验证手段（用什么实验判断 binder 成功）。

写完把报告发我（或贴在留言板），我们一起确认靶点可行再进第 2 周。不要跳过这步直接跑扩散——90% 的失败设计都源于界面定义不清。

第 2 周：界面与热点分析

预计 3–4 小时 · 产出：热点清单 + 约束定义（contig / hotspot 两行参数）

2.1 先分清两个词：界面（interface）与热点（hotspot）

界面是靶点表面上「你的 binder 将要贴上去」的那块区域；热点是这块区域里对结合贡献最大的少数残基——通常是天然复合物界面中心、疏水埋藏较多的残基，或突变后明显破坏结合的残基。扩散模型不是「看懂整个蛋白」，而是学习「用什么几何把热点残基包起来」，所以热点选得准，成功率高一大截。

2.2 最可靠的界面来源：天然相互作用伙伴

如果靶点有已知的天然结合蛋白/抗体/受体复合物结构，直接看它结合在哪，是最省力的方法。你的 binder 本质上是去抢占或模拟这块表面。实操（以任意复合物为例，链 A=靶点、链 B=天然伙伴）：

  1. ChimeraX 打开复合物：open complex.pdb；
  2. 找出 4.5 Å 内的接触残基：select :A within 4.5 of :B，然后 show sel target r 观察哪些残基在界面上；
  3. 换方向再看一遍 select :B within 4.5 of :A——你真正关心的是靶点 A 这一侧被伙伴 B 接触的残基；
  4. 截图记录界面残基，数一数它们是否在空间上聚成一块连续的 patch。

进一步可以用 PDBePISA（ebi.ac.uk/pdbe/pisa）上传复合物，读取界面残基表：重点关注 buried surface area 大、ΔG 贡献为负（稳定界面）的残基。

2.3 没有天然伙伴结构怎么办

  • 用文献突变数据：丙氨酸扫描（alanine scanning）里「突变后结合明显变差」的残基就是热点；
  • 用抗体表位数据库：如该蛋白有已知中和抗体结构，抗体结合的表位本身往往就是好界面；
  • 用保守性/功能位点：底物、辅因子、翻译后修饰周围的表面残基，生物学上常是「别的地方不该碰」的可靶向位点；
  • 结构证据：你做 cryo-EM 常遇到的小分子/肽段 density 位置，同样是天然的结合线索。

2.4 选热点的五条实用规则

  1. 选 3–8 个残基即可，宁少勿多；它们必须在空间上连成一块；
  2. 残基尽量落在较刚性的二级结构上，避开高 B-factor/无序末端；
  3. 用 ChimeraX 检查这些残基周围没有糖基化位点（N-X-S/T）或已知修饰把表面挡住；
  4. 记下链 ID + 残基编号（PDB 编号），这将是 RFdiffusion 的输入；
  5. 理想情况下热点中心应存在一个「可被包住」的几何特征：凹槽、凸起、芳香环堆叠面或疏水斑块。

2.5 准备本周标准文件

  1. 从复合物中只保留靶点单链（去掉伙伴链、水、配体、altloc），存成 target.pdb；
  2. 确认编号连续、链 ID 单一（如全是 A）；若从 PDB 下载的是 biological assembly，核对是否多了拷贝；
  3. 在文本编辑器里打开 target.pdb 抽查一遍 Cα 行，确认没有断链残留；
  4. 把热点写成一行的形式：A59,A83,A91（RFdiffusion 使用格式）。
本周最容易踩的坑 把「整个蛋白表面」都当成界面。界面定义越大，扩散越难生成一个能覆盖它的单体 binder，成功率反而下降。宁可先锁一个 3–5 残基的核心热点，跑通一轮，再考虑扩大。
本周作业：在 W1 报告基础上补 1 页「界面分析」：①界面截图（伙伴链接触面）；②热点残基列表（链+编号+一句话理由）；③糖基化/柔性检查结果；④最终 hotspot 参数串（如 A59,A83,A91）与建议 binder 长度区间。写完进入第 3 周。

第 3 周：RFdiffusion binder 模式跑通

预计 4–6 小时 · 产出：第一批 binder 骨架（建议 ≥20 条，保留 Top10）

3.1 RFdiffusion 在做什么

它从一个随机噪声骨架出发，逐步「去噪」成一个像天然蛋白的结构；binder 模式下，靶点作为固定上下文输入，模型只会对新生成的 binder 链做去噪，并且会用你给的热点残基引导 binder 去接触它们。理解输入三条信息即可：靶点 PDB、contig（谁固定 + 新链多长）、hotspot（接触哪里）。

3.2 读懂 contig 语法（重要，写错必报错）

  • 带链字母 = 来自输入 PDB 的固定片段。如 A1-150 表示输入文件 A 链 1–150 号残基原样保留；
  • 不带链字母 = 需要生成的残基长度（可为范围）。如 60-80 表示每次随机取 60–80；
  • /0 = 断链标记，表示前面一段和后面一段属于不同链（注意 README 强调斜杠后有一个空格）。

官方 binder 示例是 'contigmap.contigs=[B1-100/0 100-100]'（固定 B 链 1–100、生成 100 残基新链）。你的靶点如果整理成 A 链 1–150，想生成 60–80 残基的 binder，就写成：

./scripts/run_inference.py 'contigmap.contigs=[A1-150/0 60-80]' \
  'ppi.hotspot_res=[A59,A83,A91]' \
  inference.input_pdb=target.pdb \
  inference.output_prefix=binder_run1/design \
  inference.num_designs=8
用 Colab 的同学 官方 Colab 界面通常把 contig 和 hotspot 做成可填写的表单（字段名可能随版本变化，常见为 Contig / Hotspot residues / Number of designs）。把上面方括号里的字符串粘进去即可；本地命令行的格式则是上方整条命令。

3.3 参数怎么定

  • 长度：mini-protein binder 一般 50–100 aa。建议第一轮做两个长度带（如 60–75 与 75–95），各跑 8–16 条，观察哪个长度更容易出「干净」的折叠；
  • 步数：官方默认去噪 50 步即可；不要为了快降到 20 以下；
  • 热点数：用 W2 的 3–8 个；热点太少引导弱，热点太散模型会「平均用力」导致谁都接触不到；
  • 随机性：不同 num_designs/不同长度带就是你的多样性来源，第一轮不要只跑一条。

3.4 结果检查（本周的「眼力」训练）

  1. 下载输出 PDB（复合物结构，含靶点 + binder）；
  2. ChimeraX 打开，给 binder 链换色，观察它是否贴在你 W2 选定的 patch 上：color #2 chain B 之类自行调整；
  3. 测量 binder 与每个热点残基的最小距离：distance :B@CA :A59@CA；合格设计应至少与 3 个以上热点有接触（<6 Å）；
  4. 肉眼排除明显问题：binder 撞进靶点内部、链断裂感、大片无规则线圈、热点完全没被包住；
  5. 把通过检查的骨架各自只导出 binder 链（删掉靶点），编号存好，供第 4 周用。
报错排查清单 ①「Residue not in PDB」类错误 = contig 编号与输入 PDB 不符，去 W2 的 target.pdb 里核对；②OOM = 靶点太大，先裁剪到界面周围 10–15 Å 的残基子集再跑；③结果全像随机卷曲 = 热点串格式或链字母写错，或靶点链 ID 不是你以为的那个。
本周作业：完成 2 个长度带 × 8–16 条的设计；把每条的设计号、长度、是否接触全部热点记录到表格；挑出 Top10 骨架 + 每条的接触截图，标出你判断的依据。第 4 周将用这 10 条骨架出序列。

第 4 周：ProteinMPNN 序列设计 + 筛选

预计 3–5 小时 · 产出：候选序列集（10 骨架 × 8 序列 = 80 条左右）

4.1 为什么还需要「设计序列」

RFdiffusion 只给出主链（backbone），不决定每个位置是哪个氨基酸。ProteinMPNN 是逆折叠模型：给定骨架和「哪些位置不能动」，逐位预测最可能折叠成该骨架的氨基酸，并对每个骨架采样多条不同序列，给你多样性。

4.2 binder 场景的两个关键设置

  • 只设计 binder 链：把靶点链设为固定（fix），只重设计 binder 所在链——因为靶点序列是天然序列，不能乱改。ProteinMPNN 的 Colab 里通常可直接选链；命令行用 --pdb_path_chains 指定要设计的链，或 LigandMPNN 风格用 --chains_to_design；
  • 每条骨架采样 8 条序列：官方建议采样温度 0.1–0.3；先低温（0.1）拿高质量、后高温（0.2–0.3）补多样性。低于 0.1 会几乎退化到单一序列。

如果复杂骨架 PDB 里 binder 是 B 链、靶点是 A 链，一条代表性的本地命令是：

python helper_scripts/parse_multiple_chains.py --input_path=complex.pdb --output_path=parsed/
python protein_mpnn_run.py \
  --jsonl_path=parsed/ \
  --chain_id_jsonl=design.json \
  --fixed_positions_jsonl=fix.json \
  --num_seq_per_target 8 \
  --sampling_temp "0.1 0.2" \
  --out_folder=mpnn_out
初学者建议 先不要手写 jsonl。ProteinMPNN 官方 Colab（software 页有链接）把「设计哪条链、固定哪些残基、生成几条」做成了表单，跑通一次后再回来看命令行参数会豁然开朗。

4.3 输出怎么看

FASTA 标题行会带 score（设计的残基平均负对数概率，越低代表模型越自信）、global_score、seq_recovery 等。它们适合做相对排序，但不是实验成功率的绝对保证。同时用眼睛检查序列本身：

  • 是否出现很多未配对的半胱氨酸（除非你想设计二硫键）；
  • 核心埋藏区是否由疏水残基占主导，界面区是否有可与靶点形成氢键/盐桥的极性残基；
  • 有没有异常长的连续同一种氨基酸（聚合风险）。

4.4 筛选流水线（第 4 周末版）

  1. 按 MPNN score 排序，去掉最差 20%；
  2. 删掉序列明显有问题的（过多 Cys、过长同聚段）；
  3. 尽量保留不同骨架、不同长度带的多样性，别只留同一个骨架的 8 条近亲序列；
  4. 剩余约 40–60 条进入第 5 周 AlphaFold 回测。
本周作业：为 10 条 Top 骨架各生成 8 条序列；整理一张候选表：骨架号、序列、score、长度、是否含 Cys、你的一句话备注；输出 40–60 条待回测序列的 FASTA。

第 5 周：AlphaFold 自洽性回测 + 打分排序

预计 4–6 小时 · 产出：Top 20 设计（回测报告 + 排序表）

5.1 自洽性：设计领域的「考试」

逻辑闭环：RFdiffusion 给了骨架 → ProteinMPNN 给了序列 → 那么这条序列真的会折叠成那个骨架吗？让 AlphaFold（ColabFold）从头预测这条序列，如果预测结构和设计骨架高度一致，说明序列「记住了」目标折叠——这是目前最主流的 in silico 过滤器。对 binder 还要预测复合物：binder 与靶点是否仍贴在一起、接触残基对不对。

5.2 跑两组预测

  • 单体回测：只把 binder 序列丢进 ColabFold，看它自己能否折叠（pLDDT/pTM）；
  • 复合物回测：binder 序列 + 靶点序列一起预测（ColabFold 多链格式：两条序列之间用 : 分隔），看复合物界面的 ipTM 与 PAE。靶点序列可以从 UniProt 拿对应片段。

入门参考阈值（不同项目可微调，先当筛选线用）：

指标含义常见入门筛选线
pLDDT每个残基预测置信度核心区 ≥ 80，无大段 <50
pTM单体整体折叠置信度≥ 0.80
ipTM复合物界面置信度≥ 0.70（越高越好）
PAE两残基相对位置误差界面上目标接触残基对 < 8
骨架 RMSD预测结构 vs 设计骨架偏差核心区 < 2 Å（超叠后）
热点接触预测复合物中 binder 是否仍接触热点接触 W2 定义的热点 ≥ 3 个

5.3 排序方法（用表格而不是感觉）

  1. 在 ChimeraX 里把设计骨架与单体预测结构做序列比对后叠合，matchmaker 并看 RMSD；
  2. 打开复合物预测的 PAE 图，重点看 binder–靶点跨链区块是否大片深蓝；
  3. 把每条的 pLDDT/pTM/ipTM/RMSD/接触热点数记进同一个表；
  4. 先按「硬性门槛」筛（如 ipTM<0.6 直接淘汰），再按总分排序取 Top20。
不要神化 AlphaFold 分数 ipTM/pTM 高说明「预测认为结构合理」，不等于结合力强，更不等于实验一定成功。它筛掉的是折叠不自洽的垃圾设计；真正的亲和力要在实验中测。筛选线给得太严会把所有多样性杀光，建议先保留一批分数中等但多样性好的设计进 W6 再砍。
本周作业：完成 40–60 条候选的单体+复合物回测；填满排序表；输出 Top 20（含 FASTA、PDB、回测截图、打分表），进入第 6 周。

第 6 周：候选筛选清单 + 实验规划 + 复盘

预计 3–5 小时 · 产出：可送实验的完整设计包 + 送测清单

6.1 从 Top 20 到「送测候选」

实验名额有限，送测前再做最后一道「人工评审」，标准：

  • 序列可合成性：无长同聚段、Cys 数量合理、GC 含量正常（基因层面再查一遍）；
  • 表达可预期：疏水表面不要连成大片，N/C 端可加短柔性 linker 与表达标签；
  • 功能可解释：候选在界面上有明确的可讲故事的接触（盐桥、氢键、疏水补丁），方便以后写论文/迭代；
  • 多样性覆盖：最终 5–10 条应覆盖 ≥3 种骨架拓扑与不同长度，而不是 10 条长得几乎一样的序列。

6.2 实验衔接清单（给合作者或自己用的交付物）

  1. 序列文件：每条候选一个 FASTA + 基因合成用的密码子优化序列（可用 GenSmart/Twist 在线工具）；
  2. 结构文件：设计骨架 PDB、AlphaFold 预测单体/复合物 PDB、界面截图；
  3. QC 表：pLDDT/pTM/ipTM/RMSD/接触热点/MPNN score 汇总；
  4. 表达方案：大肠杆菌表达（周质或胞内）、是否考虑酵母表面展示做高通量结合筛选；
  5. 结合实验方案：粗筛用 pull-down/ELISA，定量用 BLI/SPR/MST；写明阳性对照（天然伙伴或已知抗体）与阴性对照（无关蛋白）；
  6. 判定标准：先写清楚「KD 到什么程度算成功」再送样，避免事后挑结果。

6.3 如果一轮全失败，怎么迭代

  • 换界面：回到 W2 换一个 hotspot patch 重来，这是最常见且最有效的改动；
  • 换长度带：60 aa 没戏就试 80–120 aa 的更长 binder，或反其道试更短；
  • 增大多样性：把 num_designs 翻倍、采样温度升高、用 partial diffusion 在已有骨架上做多样化（diffuser.partial_T=20 左右）；
  • 检查靶点准备：是否漏了糖基化、是否应该用目标构象（如 open/closed state）而非平均结构。

6.4 复盘：六周你都积累了哪些资产

  • 一条可复用的 binder 设计流水线（本页 + 三个 Colab 就是你的工具链）；
  • 靶点分析、热点清单、骨架库、序列库、回测表五层中间产物；
  • 一批「为什么失败/为什么成功」的自己的判断经验——这比任何模板都值钱；
  • 一份能放进 CV/申请材料/论文补充材料的完整项目记录。
毕业作业：把 W1–W6 整理成一份 3–5 页的「binder 设计项目报告」：背景与靶点、界面/热点定义、参数与批次记录、回测打分表、送测候选与实验方案、可能的迭代路线。这份报告就是你之后做新靶点时的母版。
